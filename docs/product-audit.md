## Discovery

The source is an implemented single-business operations application, with ADMIN, MANAGER and EMPLOYEE sessions. The root routes authenticated users to administration or employee screens. It is not an implemented generic multi-tenant SaaS. Its service and pricing rules are currently tailored to the originating cleaning/service business. Keikora is the broader product identity/direction emerging from that work, not evidence that every industry is supported today.

The key differentiator is the connected record: a booking links a customer, service details, occupied time, assigned employee, status, events, job log and payments. Assignment consumes employee availability and existing bookings. Operations users can create bookings, review recurring requests, respond to inquiries and generate invoices; employees supply availability and see their own work.

## Actual journeys

1. **Operations:** create/select customer → choose configured service and work details → create one-off/recurring booking → review pending work → choose manual/triggered automatic assignment → eligible employee assigned and booking confirmed → view schedule/status/events → prepare invoice/email where needed.
2. **Employee:** log in → set date/range time intervals → request short-notice changes through the UI when required → see assigned upcoming work and next site → record odometer readings and notes → view log history. Start/finish backend functionality does not establish a mounted start/finish screen.
3. **Admin:** operations workflow plus workforce/settings administration and availability-change approvals. Managers share operations pages but do not have every admin capability.
4. **External inquiry:** a supported intake API can create a service inquiry → operations reviews inbox → sends a configured email reply and updates status. No public customer portal or self-service booking interface is in this source.

Customer records are business data, not a CUSTOMER authentication role. Email recipients are not evidence of customer login.

## Representation and privacy decision

No source application was started or authenticated. Even read-looking dashboard page loads call notification/email dispatch functions, so requesting those pages could mutate notification records or send messages. No verified safe source demo instance was identified. No real screenshots, database records, customer names, staff details, addresses, email messages, tokens or invoice identifiers were copied.

The showcase therefore uses **faithful source-derived reconstructions** of the implemented dashboard, booking table/new-booking form, calendar, employee availability, customer table and invoice list. Screen grouping, labels and relationships come from the source components. Colors/wordmark are adapted to Keikora; every view discloses reconstruction and synthetic data. Controls presented as static examples are not fake live backend actions. The interactive tour changes views locally only.

## Final truth criteria

Implemented means code paths and interfaces exist; it does not mean commercial release or deployment verified. Configuration-dependent email, Telegram and Sheets are disclosed. Calendar synchronization is partial. Public booking, generic service editor and multi-business adaptation are development direction, not existing screens. No AI, ratings, logos, customers, revenue, pricing plans, release dates or fabricated performance metrics are claimed.
